# V26 实验记录（2026-09-17）

## 0. 结论速览

v26 = 从 `v25_16775` 出发，改两处（非对称扇区采样 + 推力门控卸力奖励），700 iter。
**结果：后向 0.60 首次从 0% 拉到 45–48%，代价是前向 0.70 从 98 掉到 90/83。**

| 模型 | 0°@0.70 | 0°@0.75 | 180°@0.55 | 180°@0.60 | 180°@0.70 |
|---|---|---|---|---|---|
| **v22best（原交付）** | **98** | 52 | 42 | 0 | 0 |
| v25_16775（后向专项） | 82 | 23 | 100 | 25 | 0 |
| **v26_17100（新折中候选）** | **90** | **58** | **50** | **45** | 0 |
| **v26_17000（后向更强）** | 83 | **58** | 48 | **48** | **18–25** |
| v26_17474（终版，弃用） | 72 | — | 63 | 0 | 0 |

（60 seeds，seed0=6000，reset_joint_noise=0.03，train 语义，每回合新建 env；
delay 语义数字几乎一致，±3pp。原始表 `v26/accept_s60.txt`）

**判定**：
- 硬约束（前向 0.70 ≥ 95%）仍未达到，**只保前向的交付物仍是 `v22/model_best.pt`**。
- 但 v26 第一次给出「前向可接受 + 后向能扛 0.60」的可用工作点。
  若接受前向 -8pt 换后向 0→45%，**`v26_17100` 是新的全面抗推候选**；
  要后向 0.70 能力选 `v26_17000`（前向再让到 83）。
- **终版必须弃用**：17474 的 180@0.60 又回到 0。好点全在中途，
  这个训练线的检查点摆动依旧剧烈，交付前必须逐点挑，不能拿 `model_final.pt`。

## 1. 训练

```
v26/train.py --task push_recovery \
  --resume v25/logs/micro_push_recovery_20260917_111219/model_16775.pt \
  --num-envs 128 --max-iters 700 --start-stage 5 --push-scale 1.0 \
  --seed 999 --learning-rate 2e-4 --save-interval 25
```

- run: `v26/logs/micro_push_recovery_20260917_142139/`，iter 16775 → 17474，约 6 分钟
- 健康度：Mean reward 35 → 90，episode length 185 → 463，entropy ≈ 19.9（无塌缩），
  action noise std 1.45。**没有出现旧线的 LR 归零 / entropy 塌缩退化。**
- 新奖励项 `yield_step` / `yield_walk` 全程有非零信号（≈0.0011–0.0015）。

## 2. 机制诊断（`step_profile.py`，mag 0.70，10 seeds，干净配置）

| 模型 | 角度 | 存活% | 抬脚数 | 沿推力位移 | 峰值倾角 |
|---|---|---|---|---|---|
| v22best | 0 | 80 | **4.2** | 0.250 | 29.0 |

  不做硬编码，换 `--data` 即可复用。
- **修 `step_profile.py`** 两处 None 崩溃：全种子在恢复前摔倒时
  `restored=None`，`np.nanmean` 与字典推导的 `np.mean` 都会抛 TypeError。
